# StudySync Development Process

## Process Model

StudySync will use a lightweight Scrum process adapted for a solo
developer. Scrum was selected because StudySync has multiple features
that can be developed incrementally, and some requirements may change
as development progresses.

The project will be organized into short sprints. Before each sprint,
work will be selected from the product backlog based on priority and
the current development needs. During each sprint, selected tasks will
be developed and tested. Completed work will be reviewed at the end of
the sprint, followed by a brief retrospective to identify improvements
for the next sprint.

## Solo Scrum Adaptation

Because StudySync is being developed by one student, the traditional
Scrum team structure will be simplified. The developer will manage the
product backlog, plan sprints, implement features, perform testing, and
review completed work.

The purpose of this adaptation is to retain the useful iterative
structure of Scrum without adding unnecessary overhead for a
single-person project.

## GitHub Project Board

The StudySync development board is maintained using GitHub Projects.
The board uses three primary columns:

- Backlog
- In Progress
- Done

Work will move from Backlog to In Progress when development begins and
to Done after the feature has been implemented and tested.

## Sprint Structure

Each sprint will have a specific goal and a limited set of backlog
items.

The general sprint workflow is:

1. Sprint Planning
2. Development and Testing
3. Sprint Review
4. Sprint Retrospective
5. Planning for the next sprint
